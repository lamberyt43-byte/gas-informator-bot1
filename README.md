# Grow And Sell — бот-информатор

Бот следит за Firebase Realtime Database игры и рассылает в Telegram:

- начало/конец ивентов (Диско, Дождь удачи и т.д.)
- новые промокоды (`dynamicCodes`)
- таблицу лидеров раз в N часов

Подписка работает через **Start**: любой, кто напишет боту, автоматически
получает приветствие и дальше все уведомления. Список подписчиков бот
ведёт сам, храня его в самой Firebase (`announcerBotState/subscribers`) —
никакой отдельной базы или сервера не нужно.

Работает **без сервера**: GitHub Actions запускает скрипт по расписанию
(по умолчанию каждые 5 минут). Каждый запуск: проверяет, не написал ли
кто-то боту (и если да — подписывает и приветствует), проверяет
изменения в игре, рассылает найденное всем подписчикам, сохраняет
состояние — и завершается. Держать компьютер или телефон включённым не
нужно.

## Файлы

- `announcer_bot.py` — сам бот (разовый запуск, не постоянный процесс)
- `.github/workflows/announcer.yml` — расписание запуска в GitHub Actions

## Установка

1. Репозиторий должен быть **публичным** — тогда минуты Actions
   бесплатны и не ограничены. В коде и файлах репозитория нет ничего
   секретного, все ключи хранятся в GitHub Secrets.
2. Firebase Console → Project Settings → Service accounts →
   **Generate new private key** → скачать JSON.
3. Repository → Settings → Secrets and variables → Actions →
   **New repository secret**, добавить:

   | Secret | Значение |
   |---|---|
   | `BOT_TOKEN` | токен бота от @BotFather |
   | `DATABASE_URL` | `https://<project-id>-default-rtdb...` |
   | `FIREBASE_SERVICE_ACCOUNT_JSON` | весь JSON из шага 2, целиком |

4. Actions → workflow **Announcer bot** → **Run workflow** — проверить
   вручную, что всё работает, не дожидаясь расписания.
5. Найти бота в Telegram и нажать **Start** — должно прийти
   приветствие (появится после следующего запуска workflow, максимум
   через 5 минут, либо запустите workflow вручную ещё раз).

## Настройка (необязательно)

Переменные окружения `LEADERBOARD_INTERVAL_HOURS` (по умолчанию `24`) и
`LEADERBOARD_TOP_N` (по умолчанию `10`) можно задать как обычные
Repository variables (Settings → Secrets and variables → Actions →
Variables) — тогда не придётся трогать код.

Чтобы люди получали приветствие быстрее после Start, уменьшите интервал
в `announcer.yml`, например на `cron: '*/2 * * * *'` (раз в 2 минуты).

## Безопасность

- Никогда не коммитьте `serviceAccountKey.json` в репозиторий — только
  через Secrets.
- Если ключ где-то засветился — сразу отзовите его в Firebase Console и
  сгенерируйте новый.
- Список подписчиков открыт для всех, кто напишет боту — если нужно
  ограничить доступ (например, только себе или списку id), нужно
  добавить проверку разрешённых chat_id в `check_new_subscribers`.
